# Changelog

Release notes for each version; earlier versions are described on the [releases page](https://github.com/Darkildo/selfsync/releases).

## Unreleased

- **Deployment, fix.** `deploy/docker-compose.yml` and the Podman Quadlet unit referred to `ghcr.io/selfsync/selfsync:latest`. That image was never published, and the `selfsync` namespace on GitHub belongs to an unrelated account, so a pull could fetch someone else's image. `deploy/docker-compose.yml` now uses the local tag `localhost/selfsync:local` and never pulls it (`pull_policy: build`); the Quadlet unit uses the project's own image (below).
- **Deployment.** A prebuilt server image is published to `ghcr.io/darkildo/selfsync` (linux/amd64 and linux/arm64), tagged `X.Y.Z`, `X.Y` and `latest`, from server 0.8.0 on: update with `docker compose pull && docker compose up -d`. GitHub Actions builds it from the published release binary (checked against `SHA256SUMS`), with an SBOM and a provenance attestation (`gh attestation verify oci://ghcr.io/darkildo/selfsync:X.Y.Z --owner Darkildo`). `deploy/quickstart` and the Podman Quadlet unit now use it; `deploy/quickstart/compose.build.yml` builds the same image locally instead.
- **Server, fix.** `selfsync gc` no longer erases a recently deleted file that was restored and deleted again while the garbage collection plan was being built: such a file now stays in the trash, with its history, until its own retention window ends. Before, the stale plan erased it at once and recorded an older `purged_seq`, so a device that had seen the restore but not the second deletion could keep the file. The background sweeper now selects and erases expired deleted files in one write transaction, closing the same race.
- **Server.** New setting `SELFSYNC_SQLITE_SYNCHRONOUS` (`sqlite_synchronous` in TOML): `full` (the new default) or `normal` (as before). With `full` an answer to a sync request means the change is on disk and survives a power loss or OS crash; it costs one `fsync` per sync request. See “Durability” in the README.
- **Plugin, desktop, fix** ([#8](https://github.com/Darkildo/selfsync/issues/8)). An error reading a file's metadata during a full scan (no permission to enter a folder, an I/O error, a network drive) no longer makes the file look deleted. Before, such a file was deleted on every other device while sync reported success; now the scan fails, sync is retried, and nothing is deleted.
- **Core, plugin and CLI.** If a full scan does not find at least 50 files that were there and at least a quarter of all files (or finds no files at all when there were 10 or more), sync stops before sending any deletions, with a notice: this looks like a disconnected drive or an unreadable folder rather than a cleanup. Bringing the files back and syncing again continues as usual. To delete them on all devices, click the notice and confirm (plugin) or run `selfsync-cli run --allow-deletes`; `run --once` exits with code 3 meanwhile. Files deleted while the app is running are not affected. For extensions: `Notice` `massDelete { count, total }` and `UiCommand` `allowDeletes`.
- **Plugin, desktop, fix** ([#9](https://github.com/Darkildo/selfsync/issues/9)). A short write (the disk or a quota is full, some network file systems) no longer leaves a truncated note in place of the downloaded one: the plugin writes the rest of the data, and if writing stops making progress the old file stays and sync reports the error. The core also compares the size of a written file with what it wrote; on a mismatch the download is retried and the truncated file is never sent to other devices as a local edit.
- **Core, plugin and CLI.** When the same Obsidian settings file was changed on two devices, the later version still wins with no conflict copy, but no longer silently: the plugin shows one notice per sync with the affected files, and the CLI logs them. The other version is in the trash or in the file's history on the server, as before. The README now says that the winner is chosen by the devices' clocks. For extensions: `Notice` `settingsOverwritten { keptLocal, keptRemote }`.
- **Plugin, desktop, and CLI, fix** ([#10](https://github.com/Darkildo/selfsync/issues/10)). A symbolic link inside the vault (to a folder or a file) no longer lets sync reach outside the vault. Before, a file from another device under a linked folder's name was written into the folder the link points to, the next full scan then took it for deleted and deleted it on every device, and a file already in the linked folder could be sent to the server as a conflict copy. Now links are not synced at all: nothing under them is read, written or deleted, entries under a link are forgotten without deleting anything on the server, and a notice names each new link once. When a link is removed, the journal is read again from the start to download what was skipped under it. Every write, rename and removal also checks that no folder on its path is a link. The sync index format is now 4 (it remembers the links); older versions of the plugin start with a safe full reconciliation after a downgrade. For extensions: `FileMeta.link` and `Notice` `linksSkipped { paths }`. On mobile Obsidian follows links itself and the plugin sees their contents as ordinary folders, as before.
- **Plugin, CLI and core, fix** ([#11](https://github.com/Darkildo/selfsync/issues/11)). A file whose name takes the full 255 bytes allowed by the file system now downloads: the temporary file next to it used to be the same name plus `.selfsync-tmp`, which no longer fits (`ENAMETOOLONG`). For such names the temporary name is now shortened to the start of the name and a hash of the path; a write interrupted at that point is still completed after a restart. Before, desktop could not receive names over 242 bytes and mobile over 235. The same applies to the CLI and to its `.trash/` (the whole path in one file name: a deep path is shortened).
- **Core, fix.** A long name in NFD (macOS, archives) whose NFC form plus the temporary suffix did not fit into 255 bytes stopped sync of the whole vault. Such a name is now normalized through a shortened temporary name, and a file system error with a single file during a scan skips that file until the next scan (it is not treated as deleted) instead of stopping the whole sync.
- Protocol is unchanged.

## 0.8.0

- **Plugin.** `main.js` is about 1.35 MB instead of 3.8 MB: the WebAssembly core and the translations (except English and Russian) are stored compressed (deflate) and unpacked at startup. Only the language Obsidian uses is unpacked; the other 69 translations stay compressed and never reach memory. In a test run under Node, loading the plugin and `onload` took about 50–70 ms instead of 70–110 ms, and the plugin used about 4 MB of memory after startup instead of 11 MB. The decompressor is part of the plugin (`plugin/src/inflate.ts`), with no dependencies, and runs on every Obsidian platform, including iOS 15, where `DecompressionStream` is not available.
- **For extensions.** `plugin/src/ext-pure.ts` is a second stable entry point without the `obsidian` package: the WebAssembly core (`initWasm` and its functions), interface strings, `lintDict` and `inflateRaw`. It loads in Node, so tests and build scripts can use it; `ext.ts` re-exports everything from it. `initWasm` accepts the WebAssembly module as is or compressed. `plugin/src/build/pack.mjs` is the esbuild plugin that compresses the core and translation registries; an extension can apply it to its own `locales.ts` (`pack({ wasm, locales: [{ registry, keep }] })`).
- Server and protocol are unchanged.

## 0.7.0

- **Plugin, desktop and mobile.** Fewer directory reads: the real name of a file (its letter case on macOS, Windows, iOS and Android) is looked up in a short-lived listing of its folder instead of reading the folder on every check, and a written file takes one check instead of three. Downloading many files into one folder no longer reads that folder 3–4 times per file.
- **Plugin, mobile.** A full scan of the vault checks up to 12 files at a time instead of one after another.
- **Core.** On the desktop, coming back to the window no longer starts a full scan of the vault if the last one was less than 10 minutes ago: Obsidian reports changes there even while the window is in the background. On mobile every return still scans, as before (`visibleScanMinMs` in the engine config).
- **Plugin, fix.** If the sync engine crashes (a panic in the WebAssembly core), sync no longer stops silently with a frozen status: the engine is recreated from the last saved index after 5 s, 10 s, … (up to 5 min). After 3 crashes in a row sync stops with a notice; “Sync now” or a click on the status bar tries again.
- **Plugin.** The sync log is kept in `sync.log` in the plugin folder (up to about 100 KB, written at most every few seconds), so after a restart of Obsidian the “Show sync log” command still shows what happened before. Settings sync never transfers this file.
- **For extensions.** `plugin/src/ext.ts` is the stable entry point for plugins built on top of selfsync (like selfsync-cloud): what it exports changes only with a note here. Sections of the settings tab have a stable `id` (`connection`, `sync`, `configSync`, `encryption`, `devices`), so an extension no longer has to pick them by their translated heading. The engine config takes `serverMinorWarn`: the protocol version below which the connection check warns that the server is older than the plugin, or `null` for no warning (an extension with its own server). CI builds and tests selfsync-cloud against every change of the core.
- Server and protocol are unchanged.

## 0.6.2

- **Core.** The sync index is written only when it changed. Before, every sync cycle rewrote it (with `fsync`) even when nothing happened — several writes a minute in idle time.
- **Core.** While downloading, the index is saved every 50 files or 2 seconds and at the end, instead of after every file: the first sync of a large vault no longer rewrites the index thousands of times. A file written after the last save is recognised by its content after a crash, as before.
- **Core, fix.** A network error in long-poll (`/v1/wait`, for example after a laptop wakes up) no longer turns long-poll off until restart: it is retried with a backoff (5 s up to 5 min), and coming back to the app retries it at once. Long-poll is still turned off when the server answers instantly (CGI).
- **Plugin, mobile.** Reading a large file in 4 MB parts no longer reads the whole file from the device for every part: the file being read is kept until it is read to the end or anything is written.
- **Plugin, fix.** Two restarts in a row (for example, a quick change of server) no longer leave two sync engines running.
- **Plugin, fix.** If the sync index cannot be read (not missing, but unreadable), the plugin shows the error in a notice, the sync log and the status bar instead of failing silently.
- **Plugin.** The status bar icon is redrawn only when the state changes.
- Server and protocol are unchanged.

## 0.6.1

- **Plugin, fix.** The settings tab no longer shows a stale state when opened. Obsidian 1.13+ keeps the rows from `getSettingDefinitions()` and draws the stored rows when the tab opens; the plugin now asks Obsidian to recompute them on every change, even with settings closed (calls in a row are merged into one). Before, a change made while settings were closed (for example, an account or status that finished loading) was not visible until something else redrew the tab.
- **Core, fix.** If the server answers `hash_mismatch` to a small file (the body arrived different from its hash), the file no longer stops the whole upload: other files are sent, this one is retried in the next round. After 3 failures in a row for the same version the version is set aside until the file changes, with a notice naming the file and a line in the sync log.
- **Server.** Database connections of a running server stay open instead of closing after 5 minutes of idle time. Closing the last connection removed the SQLite WAL, and the first write after idle recreated it with an `fsync`; on a sleeping disk (an HDD in a USB dock) that took 8–30 s while holding the write lock, and other requests failed with `database is locked`. CGI, commands and checks still close connections after idle time.
- **Server.** The request log line carries the error code of 4xx answers (`code="…"`), and `hash_mismatch` also the number of bytes received (`detail="received=N"`).
- Protocol is unchanged.

## 0.6.0

- **Plugin.** The interface follows the language of Obsidian: English, Russian and the 70 other languages of Obsidian's list. Translations other than English and Russian are machine translations; corrections are welcome as pull requests (`plugin/src/i18n/TRANSLATING.md`). The language is picked from `getLanguage()`: the exact code (`zh-tw`, `pt-br`), then the base language, then English; a string missing in a translation is shown in English.
- **Plugin.** Dates, times and size units follow the chosen language. In Arabic, Hebrew, Persian, Urdu and Dhivehi the verification digits, the recovery phrase, addresses, tokens, codes and file paths stay left-to-right.
- **Plugin.** `main.js` grows by about 2 MB because of the translations.
- **Plugin, fix.** On Obsidian 1.13+ the settings tab redraws itself again after a connection, a password, a device change and other actions finish; before, it kept showing the old state until reopened.
- Server, protocol and `selfsync-cli` are unchanged.

## 0.5.0

Protocol 1.4. Server, plugin and `selfsync-cli` 0.5.0 work with older counterparts as before; the new feature needs 0.5.0 on the server and on both devices.

### Encryption key over the connect code

A new device joins an encrypted vault without typing the password: the device that shows the code passes the key over an ECDH P-256 exchange. The server stores only public keys and the wrapped key, cannot read the key and cannot swap keys unnoticed.

- **Plugin.** If the key is unlocked on this device, «Connect a new device» shows a QR code that opens Obsidian directly and carries a one-time secret and a check of the exchange key (they never reach the server). When the new device connects, its name appears and the key is sent after «Give the key». With a code typed in by hand (or the server's link page), both screens show six digits, and the key is accepted only after they are confirmed on both devices. The new device always shows the digits, waits for the key and remembers it; «Enter the password instead» falls back to the old way.
- **CLI.** `selfsync-cli join` prints the link, QR code and code, waits for the new device and asks `y/N` before giving the key (with a typed code — after showing the digits). `selfsync-cli connect` takes `--link` (the server page or an `obsidian://` link from a QR code), receives the key (with a typed code — after you confirm the digits) and stores it in `.selfsync/key`. Both need a terminal; `--no-handoff` turns the exchange off, Ctrl-C stops it (exit code 130). The QR code with the secret stays in the terminal scrollback: the secret works once and gives nothing without your consent.
- **Server.** `JoinCreate.commit`, `JoinToken.handoff_commit` and `POST`/`PUT`/`GET`/`DELETE /v1/join/handoff`; a read-only device may take part in its own exchange (`PUT`, `DELETE`) and nothing else. The wrapped key is served again until the new device closes the exchange, and either side can cancel (`JoinHandoffSource.cancel`, `DELETE`) — the other one learns it on the next poll; after «Don't give» or a QR mismatch the device that showed the code offers to revoke the new device. Network errors and 5xx do not abort the exchange: clients retry with a growing pause. Exchanges live 10 minutes after the new device joins, `selfsync sweep` removes expired ones together with keys and wrappings.
- **Core and WASM.** The exchange is one module (`selfsync_core::handoff`) with a domain label; WASM exports its primitives for add-ons. Test vectors are in `spec/vectors/handoff.json`. Details: `spec/protocol.md`, «Передача ключа по коду».
